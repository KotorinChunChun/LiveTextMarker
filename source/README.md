# Pointer Underline

Windows 10 / 11（64 bit）用。ポインタの位置にある文章を検出し、折り返しを含む各表示行の行頭から行末まで下線を表示するプレゼンテーション補助アプリです。

## 起動

1. ZIPをすべて展開してください（ZIPの中から直接実行しないでください）。
2. `app/PointerUnderline.exe` を起動してください。
3. 「開始 / Start」を押し、文字の上にポインタを移動してください。
4. 発表中は「通知領域へ」で設定画面を隠せます。通知領域アイコンのダブルクリックで戻ります。

- Ctrl + Alt + U：開始 / 一時停止
- Ctrl + Alt + Q：終了
- 設定画面：表示方法（下線／塗り）、太さ、上下位置、色、塗りの濃さ、OCRの有効 / 無効、Ctrlモード
- 塗りは初期状態で黄色・濃さ16%の半透明表示です。濃さを8～30%に調整できます。下線と塗りの色は別々に保持し、表示方法・塗りの色・濃さも再起動後に保持します。
- 「Ctrl押下で実行」をオンにすると、開始・一時停止の状態にかかわらずCtrl押下中に認識・表示します。開始ボタンとCtrl + Alt + Uは独立した常時表示の切り替えです。一時停止中はCtrlを離すと消え、開始中は離しても表示を続けます。
- 上下位置は初期値 -2.0。負の値で上、正の値で下へ移動し、-30.0～30.0を小数で調整できます。上下位置・太さ・色・OCR・Ctrlモードは再起動後も保持します。
- 現在の検出方式・行数と直近10件のログを表示します。ログに画像や本文は含めず、終了時に破棄します。
- ショートカットが他のアプリと競合する場合は通知領域メニューを使ってください。
- ウィンドウの × は終了です。起動時は停止状態です。

実行ファイルは未署名です。組織の実行制限やセキュリティ警告を無効化しないでください。必要なら管理者に確認してください。管理者として実行する必要はありません。

## 認識の仕組み

まず UI Automation の TextPattern からポインタに対応する段落を取得し、同じ表示行の文字断片を結合します。文字が取得できない場合、UI Automationから取得した対象ウィンドウ・フレーム内のポインタ付近の領域を一時的にキャプチャし、同梱した Tesseract の日本語・英語モデルで段落を認識します。折り返しの各行へ下線を表示し、行の右側の空白や行間にポインタが移ると線を消します。別段落や別列を無条件には連結しません。撮影と描画の両方を同じフレーム内に制限し、手前に重なる別ウィンドウの領域も除外します。UI Automationから対象領域を取得できない場所ではOCRを実行せず表示を停止します。

ポインタが約65ミリ秒静止してから認識し、UI Automation は通常約180ミリ秒ごとに更新します。OCRは画像サイズ・PC性能によりさらに遅くなります。ポインタをずっと高速で動かす間は新しい下線を表示せず、短く止めると追従します。認識できない場所に古い線を残さないことを優先しています。

画像・認識したテキストはファイル保存も外部送信もしません。OCR画像はメモリ中に短時間保持されます。ネットワーク通信・テレメトリ・自動起動・権限昇格は実装していません。UI Automationでパスワード欄と判別できる箇所はキャプチャしませんが、すべての独自描画の機密欄を検知できるわけではありません。機密情報の表示中は一時停止してください。

下線はマウス入力を透過し、フォーカスを奪わない最前面ウィンドウです。表示・移動・消去をアクティブ化しない操作に統一しています。Windows 10 2004以降では、OCR撮影中だけ下線をキャプチャ対象から外し、画面上の表示を維持します。撮影後は通常の画面共有に戻します。除外APIを使えない環境では一時非表示へ戻し、ログに「互換モード」と表示します。

## OCRの前提

.NETランタイムは `app` に同梱されています。OCRのネイティブDLLには Microsoft Visual C++ 2015–2022 x64 Redistributable が必要です。OCRエラーの場合は公式サイトの案内を確認してください（アプリは勝手にインストールしません）。

https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist

日本語・英語の横書きを対象にしています。縦書き、回転文字、装飾文字、極小文字、複雑な背景、低コントラスト、特殊なPDFや独自UIでは検出失敗や幅の誤差が生じます。OCRは字形の下端、UI Automationは提供元の行ボックス下端を基準とするため、「下の間隔」で調整してください。モニターをまたぐ行はポインタ側のモニターで切り取ります。

## 発表前の確認

- PowerPointの実際のスライドショーで日本語・英語の行にポインタを置く
- 次の行・別の列・空白に移動し、前の線が消えることを確認
- 設定画面からOCRを切り替えて比較
- マウスクリック・スクロール・スライド送りが妨げられないことを確認
- 拡大率が異なる複数モニターで位置が合うことを確認
- 画面共有は「画面全体 / ディスプレイ」を選び、受信側で下線が見えることを確認。特定アプリだけのウィンドウ共有では別ウィンドウの下線は通常含まれません

排他的フルスクリーン、保護された映像、ロック画面/UACの安全なデスクトップ、管理者権限アプリ等では利用できないことがあります。画面上に表示された内容のみが対象です。

## ソースからビルド

`source` フォルダーで .NET 8 SDK を使います。PowerShell 7 またはWindows PowerShellから実行できます。

```powershell
./Build.ps1
```

出力は `out/PointerUnderline/PointerUnderline.exe` です。スクリプト実行が組織の方針で制限されている場合、方針を変更せず以下のコマンドを実行してください。

```powershell
dotnet run --project tests/GeometryTests.csproj -c Release
dotnet publish PointerUnderline.csproj -c Release -r win-x64 --self-contained true -p:Platform=x64 -o out/PointerUnderline
```

ビルド時のみNuGetから依存パッケージとMicrosoftランタイムをダウンロードします。実行時はオフラインです。

## 検証と限界

UIA／OCRと下線／塗りの4通りで隣接フレーム・重なる別ウィンドウを越えないことを実機確認し、38件の自動テストを通過しました。詳細は [対象領域の検証記録](../dev/testing/20261010-対象領域制限.md) を参照してください。

2026-10-10 に Windows 実機で、UI Automationの色付き文章・3行折り返し・文章末尾、添付2画像のOCR・最終行、Ctrl押下中のみの表示と解除時の消去、ログ欄の配置と検出ログを確認しました。26件の自動検証も成功しています。詳細は [改善記録](../dev/testing/20261010-認識改善.md) を参照してください。下記は初版時点の記録です。

このリリースはLinuxからWindows向けにクロスコンパイルしています。C#のビルドと座標選択・DPI・空白判定の自動テストを行います。Windows上でのUI Automation、ネイティブOCR DLL、実際のPowerPoint、入力透過、画面共有のエンドツーエンド確認は未実施です。発表前に上記チェックを必ず実施してください。

認識は隔離した補助プロセスで行います。UI Automationが650ミリ秒、OCRが2.5秒（補助プロセス・OCRの初回起動は最大5秒）を超えると補助プロセスを終了して次回再起動します。設定画面や終了操作を認識待ちで固めず、古いポインタ位置の結果も破棄します。遅いPCではOCRタイムアウトに達することがあります。
