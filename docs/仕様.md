# LiveTextMarker 仕様書

対象版：1.1.0。更新日：2026-10-10。

## 名称と画面

| 項目 | 現行仕様 |
|---|---|
| アプリ名・実行ファイル | LiveTextMarker / `app/LiveTextMarker.exe` |
| 設定画面タイトル | `設定 - LiveTextMarker - ver X.Y.Z`。版番号はアセンブリから取得する |
| 設定画面の見出し | なし |
| 通知領域 | LiveTextMarkerと常時表示の状態を表示 |
| × | 設定画面を非表示にしてトレイへ格納。プロセスと認識機能は継続 |
| 真の終了 | 右下の「アプリを終了させる」、同名のトレイ項目、設定した終了キー。OS終了時にも終了する |

## 実行条件

実行条件は「常時表示が開始状態、またはCtrl押下で実行が有効かつCtrl押下中」。Ctrl押下で実行は初期設定でオン。常時表示の状態は保存せず、起動時は一時停止とする。

| 常時表示 | Ctrl押下で実行 | Ctrl | 結果 |
|---|---|---|---|
| 開始 | 任意 | 任意 | 表示対象があれば実行 |
| 一時停止 | ON | 押下 | 表示対象があれば実行 |
| 一時停止 | ON | 非押下 | 消去して待機 |
| 一時停止 | OFF | 任意 | 消去して待機 |

## キー設定

開始／一時停止とアプリ終了の2行を設ける。各行はCtrl、Alt、Shift、Winのチェックボックスを横並びにし、右端に「なし」とKeys列挙型のキーコード一覧から選ぶコンボボックスを置く。この形式を他のプロジェクトでも使う推奨方式とする。

- 既定は開始／一時停止がCtrl+Alt+U、アプリ終了がCtrl+Alt+Q。
- 修飾キーのみの場合は押下状態を検出し、押し始めに1回実行する。すべて未選択で「なし」は無効。
- 通常のキーはWindowsのグローバルホットキーに登録する。選択できても、OS予約や他アプリとの競合などで登録できないキーは画面に通知する。
- 同じ有効な割り当てを2行に指定した場合は両方を無効化し、重複を通知する。
- 変更時に登録を更新し、その都度設定を保存する。

## 強調と認識

下線／塗りを切り替える。下線の太さは1～12、上下位置は-30.0～30.0で既定-2.0。DPIに合わせて整数の太さに丸め、各行で同じ高さを使用する。境界付近では太さを削らず位置を調整し、線全体が収まらない場合は消去する。塗りは黄色・濃さ16%が既定で、8～30%に制限する。下線と塗りの色は別々に保持する。

UIAを優先し、本文・ボタン・リンク・タブ見出しなど最寄りの要素を認識境界とする。必要時はその領域内でOCRを行う。画像、文字矩形、描画を境界内に制限し、重なる別ウィンドウを除外する。対象領域が得られない場合に全画面OCRへ広げない。非同期処理後に対象ウィンドウ・要素の識別子・範囲を再確認し、不一致なら結果を破棄する。

Ctrlを離した場合は常時表示の状態に従う。行末の空白・行間・対象外へ移動した場合も消去する。本文の折り返しは各表示行の末尾まで扱い、別の要素を無条件に結合しない。

## 保存と互換性

OCR、Ctrl押下で実行、太さ、上下位置、2種類の色、表示方法、塗りの濃さ、2種類のキー割り当てを保持する。既存設定にキーがない場合は既定値で補う。設定保存先は `%LOCALAPPDATA%/LiveTextMarker/settings.json`。新保存先から読み込めない場合は、旧保存先 `%LOCALAPPDATA%/PointerUnderline/settings.json` を読み込み、新保存先へ保存して引き継ぐ。旧ファイルは削除せず、移行保存に失敗しても旧設定を使用する。

作業フォルダーは `C:/develop/test/LiveTextMarker`、プロジェクトファイルは `source/LiveTextMarker.csproj`、内部名前空間とMutexもLiveTextMarkerに統一する。旧名は設定移行元と過去の記録だけに残す。本文や画像は保存・送信せず、直近10件の方式・範囲・結果のログだけをメモリに保持する。

## 確認範囲

現行仕様と実測済みの範囲を混同しない。[確認記録](../VALIDATION.md) に過去の実測と未測定事項をまとめる。ユーザーの「テスト不要」に従い、設定画面更新以降は新しい動作テストを実行していない。

## レイアウト

キー設定と表示設定を白いパネルでまとめ、ラベル列と入力欄の位置を揃える。状態表示は操作行の右、ログは残りの高さ、終了ボタンは右下とする。見出しは追加しない。[デザインと生成条件](design/README.md) を参照。

## 文字付近の許容幅と本アプリ

候補選択・結果採用・表示維持では文字の行の高さの25%を許容幅とし、3～6ピクセルに制限する。文字矩形内の候補を優先する。要素・ウィンドウ境界と描画範囲は広げない。本アプリ自身の設定画面も対象とし、描画用オーバーレイだけを対象外とする。UIA要素取得とTextPatternによる行矩形取得は区別し、TextPatternがない場合は境界内のOCRを使用する。
