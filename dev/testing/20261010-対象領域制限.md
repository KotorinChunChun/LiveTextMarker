# ウィンドウ・フレームの境界を越える認識の修正

> 現行仕様への参照：この資料は作業当時の記録です。最新の名称・操作・仕様は [LiveTextMarker仕様書](../../docs/仕様.md) を参照してください。

## 方針

- UI Automationでポインター配下の文書・編集欄・ペイン・表など最寄りのフレーム領域と識別子を取得し、UIAの文字矩形とOCR画像を同じ領域へ制限する。
- 広い親のTextPatternへ置き換えず、最初の有効な文字範囲を使用する。
- 他ウィンドウで隠れた部分をZ順序から除外し、ポインターを含む安全な矩形だけ撮影・描画する。
- 非同期認識後にフレーム識別子と領域を再取得し、変化した結果を破棄する。対象領域を取得できない場合は全画面OCRへ戻さず表示を消す。
- 描画時にも領域でクリップし、認識後のウィンドウ重なり変更も再確認する。

## 検証

- [x] 領域クリップ、重なり除外の自動テストとビルド。
- [x] 同じウィンドウ内の隣接フレームでUIAとOCRを検証。
- [x] 別ウィンドウの重なり、境界での描画制限を検証。
- [x] 既存の複数行・Ctrl・塗り・点滅の回帰確認と配備版の再起動。

## 実測結果（2026-10-10）

- 自動テスト38件とReleaseビルドが成功。配備版を更新し再起動済み。
- `境界検証.ps1` をUIA／OCR × 下線／塗りの4通りで実施。左右のフレームの文字範囲が各フレーム内に収まり、手前の別ウィンドウを越えないことを実際のオーバーレイ矩形で確認した。カバーを閉じた後も隣のフレームへ伸びなかった。
- `認識検証.ps1` で段落の先頭行・最終行から3行の行頭と行末を確認。`操作検証.ps1 -Highlight -Dark` でCtrl押下時の3行表示、解除時の消去、検出ログを確認した。
- `点滅検証.ps1 -Ocr -Highlight -AssertStable` の独立した6秒測定では383サンプル中の消失0、非表示イベント0、前景切替0。空白で消去し文章で再表示、Ctrl解除時の消去も成功した。
- 最初の点滅測定には別の境界試験の画面操作が重なったため、その測定を無効として単独で再実施した。認識処理自体の障害とは扱わない。
- 検証用プロセスの終了はPIDを指定してWM_CLOSEを送り、終了を待つ方式へ変更した。

## 制約

UIAが対象領域を提供しない場所ではOCRを実行せず表示を停止する。手前のウィンドウを矩形として除外するため、透過・不定形ウィンドウでも保守的に範囲を狭める。添付の実アプリそのものの再現試験は行っておらず、境界構成を再現した専用画面で測定した。
