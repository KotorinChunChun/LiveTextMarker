# Discordの本文外へ伸びる範囲の修正（2026-10-10）

## 原因と変更

Discord実機のUIAで、本文のText要素から取得したParagraphの矩形に時刻の別要素が含まれることを確認した。前回は最寄りのGroupを境界としたため、同じGroup内の本文外の矩形が残っていた。

- [x] Text、Button、Hyperlink、ListItem、TreeItemも対象境界として採用し、最寄りの具体的な要素でUIAとOCRの範囲を制限する。
- [x] 対象境界にTextPatternがない場合は、その親の広いTextPatternへ探索を進めず、その境界内のOCRへ移る。
- [x] 同じプロセス内でもポインターのネイティブウィンドウが要求元と異なる結果を破棄する。
- [x] 本文外の時刻・サイドバー・入力欄の除外と、折り返しの最終行の維持を回帰テストへ追加する。

## 検証結果

- 40件の自動テスト、Releaseビルド成功。
- 実際のDiscordで15個のText要素を検証し、描画候補の矩形は全てそのText要素内に収まった。複数行の要素4個も認識した。本文・名前・入力内容は記録していない。
- 通常のRichTextBoxの3行段落で先頭行・最終行から行頭と行末を認識できた。
- 配備版を更新して再起動し、OCR塗りの左右フレーム・別ウィンドウの重なり除外を確認した。

## 制約

Discordの表示状態によりUIA階層が変わるため、添付画像と完全に同じ画面状態の再現ではない。文字の途中でUIA要素が分かれる場合は、要素を越える誤検出を避けるためその要素内で表示する。
- OCR塗りの6秒測定は384サンプルで消失0、非表示イベント0、前景切替0。キャプチャ設定の復元、空白で消去・再表示、Ctrl解除を確認。最終状態は下線表示・Ctrl待機中。
