# 下線の点滅とアクティブウィンドウ切り替わりの改善

## 調査と方針

- 下線更新で Form.Bounds・Show・Hide とネイティブ SetWindowPos が混在していた。位置変更・表示・非表示を SWP_NOACTIVATE 付きのネイティブ操作に統一し、同じ範囲の再表示を省く。
- OCR撮影前に毎回 HideLines を呼んでいたため、撮影頻度に応じて下線が一時的に消える経路が存在した。
- Windows 10 2004以降では、OCR撮影の同期処理中だけ下線をキャプチャから除外し、画面上では表示を維持する。finallyで通常のキャプチャ可へ戻す。永続的に画面共有から除外しない。
- 除外APIが利用できない場合だけ従来の一時非表示へ戻し、画面ログに互換モードを表示する。
- ユーザーの対象アプリ上での現象と、検証画面での実測を区別する。

## 検証

- [x] ビルド・既存自動テスト：26件成功。自己完結型 win-x64 Release publish 成功。
- [x] UIAとOCRの反復検出中の前景ウィンドウ変更と下線表示・非表示イベントを計測した。
- [x] Ctrl解除、空白への移動での消去と文章への移動での再表示、Ctrlモードの複数行表示を確認。既存の上下位置・Ctrlモードを保持。
- [x] 検証済み配備版を更新・再起動。PID 37720で応答、開始済み・Ctrl待機中を確認。

## 原因の再現と修正後の実測

検証用の画像文章へポインターを置き、Ctrlを押したまま6秒間、Windowsの前景変更イベントと下線ウィンドウの表示・非表示イベントを監視した。各15msのサンプルで下線の存在も確認した。

| 測定 | 修正前 OCR | 修正後 OCR | 修正後 UIA |
|---|---:|---:|---:|
| 下線の非表示イベント | 100 | 0 | 0 |
| 下線の表示イベント | 100 | 0 | 0 |
| 対象以外への前景変更 | 100 | 0 | 0 |
| 全下線が消えたサンプル | 24 / 382 | 0 / 381 | 0 / 382 |
| 撮影除外設定の通常状態への復元 | 正常 | 正常 | 正常 |

修正前はOCRのHide/Showで対象以外への前景切り替えも繰り返された。下線の位置・表示をForm.Bounds/Show/Hide経由で操作し、SWP_NOOWNERZORDERがない経路も残っていた。下線更新をSWP_NOACTIVATE・SWP_NOOWNERZORDER付きのネイティブ操作へ統一し、OCR撮影時のHide/Showを除去したことで、同一の検証画面で前景変更と消失が0になった。

さらに修正後OCRで空白への移動・文章への復帰のどちらも前景を保持し、Ctrl解除時には消去することを確認。UIAの3行表示と検出ログ欄の既存実機検証も成功した。

機械可読の証跡は `点滅実測-OCR-修正前.json`、`点滅実測-OCR-修正後.json`、`点滅実測-UIA-修正後.json`。

## 再現コマンド

アプリを起動して、PowerShell 7で以下を実行する。実機のカーソルとCtrlを使うため操作を控える。検証対象は自前の文章画面のみで、対象アプリの本文を記録しない。

```powershell
cd C:\develop\test\PointerUnderline
pwsh -NoProfile -File dev/testing/点滅検証.ps1 -Ocr -AssertStable
pwsh -NoProfile -File dev/testing/点滅検証.ps1 -AssertStable
pwsh -NoProfile -File dev/testing/操作検証.ps1
```

ユーザー添付画面のアプリそのものを自動操作しての確認は実施していない。撮影除外APIが利用できない古いWindows等では互換モードの一時非表示が残る。画面共有に対する恒久的な除外はせず、撮影の同期処理後に解除する。

仕様参照：[SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)、[SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。
